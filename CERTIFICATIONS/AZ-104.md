# Adminitster Identity 
## Azure Entra ID
- identity and access management
- = center of applications
- access to
	- m365
	- dropbox
	- concur
	- salesforce
- ssrp
	- self service password reset (SSRP)
- authentication
	- single sign on (SSO)
### concepts
- identity
	- any object that can be authenticated
		- user
		- group
		- managed identity (identity of a service within AZ)
			- identity of a VM
		- service principle
			- same as service accounts on prem
			- execute on behalf of user
- account
	- associate data attribute to identity
	- example
		- user will have multiple attributes
			- address
			- phone number
- entra ID account
	- created in entra ID / another AZ cloud service
	- example
		- work or school account
		- personal microsoft account
- entra ID / tenant / directory
	- dedicated instance of entra ID
	- created during microsoft cloud service
	- tenant = directory
### editions
- entra ID
	- queried using http/https
	- saml / ws-federation / openID connect / oath = seamless
	- federation with 3rd party providers
	- managed service offering
- active directory domain services
	- queried using ldap
	- kerberos = outdated
	- federation only to other domains
		- 3rd party services not supported
	- adds will be running on vms or physical servers

## device identities (optional)
- registered devices
	- permit personal device use
	- login via individual microsoft accounts
	- link to user accounts
	- managed by intune
	- support for W10, IOS
	- example
		- personal phones
		- personal tablets
- joined devices
	- ideal for cloud centric organizations
	- require company login
	- support W10 and newer OS
	- example
		- company on devices
- hybrid joined devices
	- on cloud and on prem 
	- both ADDS and entra ID
	- managed by group policy
	- support for W7 and above
## user accounts
- foundational element
- gateway to secure workspace
- digital passport
- all users must have an account
- each user account can have optional properties
	- address
	- department
	- ...
- all users can be access from entra ID > users > all users
- types
	- cloud identities
		- standalone accounts
		- no dependencies from on prem
		- fully embracing the cloud
	- guest accounts
		- created for external users
	- directory synchronized users
		- users from on prem AD to the cloud using entra ID connect (Azure AD connect)

## group accounts
- group tyes
	- security groups
		- azure admins
			- grant AZ permissions on 
	- m365 groups
		- oriented towards collaborations
		- intigrate with m365: powerpoint, excel, onenote
